# Personal Compounding OS — 产品规划 v0.1

> 记录你拥有的，计算你消耗的，衡量你积累的，预测你未来的。

- 状态：已评审定稿（2026-08-12），可作为 MVP 开发依据
- 配套文档：[架构文档](./architecture_v0.1.md)

---

## 1. 产品定位

**一句话**：帮你计算人生长期回报的个人操作系统（Personal Compounding OS）。

**MVP 切入点**：「我的东西到底值不值？」——把每一件耐用品和消耗品的**真实持有成本**（日均成本、单次使用成本）算清楚，让"贵不贵"变成"划不划算"。

**产品性质**：self-hosted 个人工具，先做给自己用，数据完全归用户所有，可随时导出。不考虑早期商业化。

**与市面产品的区别**：记账 App 记录的是"花了多少钱"（购买价格）；本产品计算的是"这笔钱正在以什么速度被消耗、换回了什么"（真实消费成本）。核心视角从「消费记录」转向「资产经营」。

---

## 2. 产品原则（评审后确立的硬约束）

这五条原则约束所有版本的设计，不随迭代妥协：

1. **估算优先于记录**。不要求用户逐次打卡。录入时选「使用频率档位」，系统按估算折算成本，用户偶尔校准即可。逐次记录只作为可选的补充手段。
2. **消耗品只记"用完了"**。不记剩余量。买新的那天点一下「上一瓶用完」，系统自动算出实际消耗周期和每日成本。
3. **所有推算输出区间化 + 假设可见**。展示形如「按你填的使用频率，单次成本约 5~8 元」，每个数字的假设（频率档位、预计寿命、残值）可点开查看并直接修改，修改即校准。**禁止输出无法溯源假设的精确数字。**
4. **算清楚账，不替用户裁决**。决策引擎只做确定性算术（持有成本 vs 机会成本对比表），不输出「Buy / Don't Buy」结论。
5. **数据开放**。事件级数据可完整导出（JSON/CSV），无 lock-in。

## 3. 目标用户与北极星指标

- **第一用户**：作者本人（self-hosted）。
- **画像**：长期主义者 / 效率与量化爱好者，愿意为"算清楚账"付出少量录入成本的人。
- **北极星指标**：**30 天后仍在录入或校准数据的用户比例**（自用阶段即"第 30 天我自己是否还在用"）。这个指标不过关，后续所有模块（目标、决策、AI）都是空中楼阁，不启动。

## 4. 核心概念与指标口径

### 4.1 资产分类（MVP）

| 类型 | 定义 | 例子 | 成本模型 |
|---|---|---|---|
| 耐用品 Durable | 多次使用、随时间/使用折旧 | MacBook、相机、家具、鞋 | 折旧摊销 + 使用频率估算 |
| 消耗品 Consumable | 用完即止、周期性回购 | 洗发水、咖啡、猫粮、牙膏 | 消耗周期实测 |

### 4.2 使用频率档位

录入耐用品时必选一档（后续可校准）：

| 档位 | 折算区间（次/月） |
|---|---|
| 每天多次 | 60 ~ 120 |
| 每天一次 | 25 ~ 31 |
| 每周几次 | 8 ~ 16 |
| 每周一次 | 3 ~ 5 |
| 每月几次 | 1 ~ 3 |
| 极少 | 0 ~ 1 |

档位天然是区间，这是所有「单次成本」输出区间化的来源之一。用户也可填自定义频率（如「每周 2 次」），此时区间收窄为 ±30%。

### 4.3 耐用品指标口径

设：购买价 P、预计寿命 L（月）、预计残值区间 [R_min, R_max]、累计维护成本 M、已持有天数 D、频率区间 [f_min, f_max]（次/月）。

| 指标 | 口径 | 输出形式 |
|---|---|---|
| 全周期日均成本 | (P − R + M_预估) / (L × 30) | 区间（由 R 区间产生） |
| 已实现日均成本 | (P − 当前估值 + M) / D | 区间（由当前估值区间产生） |
| 估算累计使用次数 | f × (D / 30) | 区间 |
| 单次使用成本 | 已实现持有成本 / 估算累计使用次数 | 区间 |
| 剩余价值 | 线性折旧至残值：P − (P − R) × min(D, L×30) / (L×30) | 区间 |
| 使用率评级 | 频率档位 vs 同类目参考频率 | 高 / 中 / 低 |

当前估值默认由线性折旧推得；用户可手动录入估值（例如参考二手行情），录入即成为新假设。

### 4.4 消耗品指标口径

- **消耗周期** = 「用完」打卡日 − 开始使用日（实测，不估算）。
- **每日成本** = 购买价 / 消耗周期天数。
- 首瓶未用完前：以品类默认周期给出区间预估，明确标注「预估，待首次用完后转为实测」。
- 多次回购后：用历史周期的分布给出「预计下次用完日期」区间，并对比历史每日成本走势（贵的那瓶到底是不是更贵）。

### 4.5 假设面板（原则 3 的载体）

每个指标数字旁有「假设」入口，点开显示：

```text
单次使用成本 ¥5.2 ~ ¥8.1

基于以下假设：
· 使用频率：每周几次（8~16 次/月）   [修改]
· 预计寿命：5 年                    [修改]
· 预计残值：¥1,500 ~ ¥2,500         [修改]
· 数据来源：你在 2026-08-12 的录入
```

修改任何假设立即重算并记录为一次校准事件（可回溯）。

## 5. MVP 范围（Phase 1）

> **实现状态（2026-08-12）**：Phase 1 功能清单已全部落地，包含周报摘要页（`/weekly`）与月度轻校准提醒（周报页内「待校准提醒」，超过 20 天未校准即提示，取最久未校准的 3 件）。耗时/自动化的「可选邮件」形态暂未做（self-hosted 无邮件基础设施），当前是「打开即生成」的站内滚动 7 天摘要，功能等价，留作后续按需补充。另新增：耐用品成本模型区分按天/按次计成本、快速校准使用次数、资产四象限可点击下钻、衣物/床品季节性适配（详见架构文档变更记录）。

### 5.1 功能清单

**资产录入（耐用品）**
- 字段：名称、类目、购买价、购买日期、预计寿命（给类目默认值）、预计残值（默认按类目残值率区间）、使用频率档位。
- 录入一件资产 ≤ 30 秒，除名称和价格外全部有默认值。

**资产录入（消耗品）**
- 字段：名称、类目、购买价、（可选）容量、开始使用日期。
- 「用完了」按钮：一次点击关闭当前周期、可顺手录入回购的下一瓶。

**校准机制**
- 假设面板随处可改（见 4.5）。
- 周期性轻校准：每月对 2~3 件资产提问「过去一个月大概用了几次？」，一次点击完成。
- 可选的「用了一次」快捷按钮，供想精确记录的资产单独开启，不默认。

**资产列表与详情**
- 列表：按单次成本 / 日均成本 / 价值排序与筛选。
- 详情：全部指标 + 假设面板 + 事件时间线（购入、校准、维护、估值、用完）。

**Dashboard（你的资产账本）**
- 物理资产总值（区间）、今日资产成本合计（区间）。
- 四象限：高/低价值 × 高/低使用频率，标出「低频高值」资产的总额（潜在可释放现金）。
- 消耗品：进行中的周期、预计用完日期、每日成本排行。

**周报（留存钩子）**
- 每周一封摘要（站内页 + 可选邮件）：本周资产成本、消耗品动态、最值/最不值 Top3、待校准提醒。周报是用户"明天还回来"的核心理由，MVP 必做。

**数据导出**
- 一键导出全部事件与资产（JSON/CSV）。

### 5.2 明确不做（MVP 非目标）

- 金融资产、时间记录、能力/知识资产、目标系统、AI 建议、多用户、移动 App、自动导入账单。
- 不做「Buy / Don't Buy」裁决（永久原则）。
- 不做剩余量记录、不做逐次打卡的强制要求（永久原则）。

### 5.3 MVP 验收标准

- 录入 20 件真实资产 + 10 件消耗品，全流程无卡点。
- 每个展示出的成本数字都能点开假设并修改。
- 连续使用 30 天后仍有校准行为（北极星自测）。

## 6. 路线图

```text
Phase 1  资产成本 MVP（web）          ← 当前
Phase 2  金融资产 + AI 周报洞察
Phase 3  目标系统 + 决策对比引擎
Phase 4  iOS + 自动化捕获 + 生态联动
Phase 5  远景：人生资本（时间/能力/健康/关系）
```

### Phase 2：金融资产 + AI 洞察

- 金融资产手动记录余额快照（现金、存款、基金、股票等），趋势与净增。国内无开放银行 API，不做自动同步，靠低频快照（每月一次即可成图）。
- AI 洞察从**周报摘要**这一低风险形态起步：总结本周数据、指出低使用率资产、提示待校准项。不做每日人生建议。
- AI 为可选开关；支持接本地模型（Ollama）以守住 self-hosted 隐私底线，详见架构文档。

### Phase 3：目标系统 + 决策对比引擎

- **目标系统第一版只做单一储蓄目标 + 确定性推算**：给定当前净资产、月储蓄、收益率假设（区间），输出达成时间区间；假设面板同样适用。反推展示「收入 +X% / 储蓄率 +Y% / 收益率 +Z%」各自对达成时间的影响（敏感性对比表），不推荐方案。
- **决策对比引擎**：输入一个候选购买（价格、预计寿命、预计频率），输出对比表——

```text
              买入并持有 5 年        不买、同额投资 5 年
总成本/终值    ¥9,800 ~ ¥11,400      ¥16,300 ~ ¥18,900（按年化 4%~7%）
单次使用成本   ¥5.2 ~ ¥8.1           —
所有假设可点开修改；系统不给结论。
```

### Phase 4：iOS + 自动化捕获（产品规划保留，落地方案见架构文档 §8）

自动化是移动端的强项，这一阶段的目标是把「录入成本」进一步压到接近零：

| 能力 | 载体 | 解决什么 |
|---|---|---|
| 快捷指令 / Siri（App Intents） | iOS | 「嘿 Siri，相机用了一次」秒级打卡 |
| NFC 标签 → 深链打卡 | iOS + 实体标签 | 高价值物品贴标签，碰一下即记录 |
| 桌面小组件 | iOS Widget | 今日资产成本常驻可见，强化留存 |
| Screen Time（DeviceActivity） | iOS | 数字资产/订阅的真实使用时长自动采集 |
| 拍照/截图 OCR 导入 | VisionKit | 小票、订单截图 → 草稿购入事件 |
| HealthKit | iOS | 远景健康资产的数据底座 |

前提：web 端 API-first 架构从第一天保证 iOS 客户端可直接复用同一套 API（架构文档 §4、§8）。

### Phase 5：远景（保留在规划中，不进 MVP/二期）

- 时间资产：24 小时资产配置视图，时间投入 → 长期资产的复利链。
- 知识/能力资产与**能力 ROI**、**人生 ROI（Life ROI）**：因果归因不可靠，故永远以「用户自述 + 区间展示」形态存在，不做自动归因；作为世界观与愿景牵引，而非计算承诺。
- 健康资产、关系资产。
- AI 从「周报摘要」演进为 Personal CFO：消费模式分析、资产配置提示、机会与风险提醒——仍遵守原则 4，提供分析不做裁决。

## 7. 页面结构（信息架构）

MVP 三个页面 + 一个弹层：

```text
① Today / Dashboard      今天发生了什么、资产账本四象限、周报入口
② Assets                 资产列表（耐用品/消耗品 Tab）、录入、详情
③ Settings               导出数据、类目默认值管理、周报开关
④ 假设面板（全局弹层）     任意指标点开 → 查看/修改假设
```

Phase 3 后新增 `Goals` 与 `Compare`（决策对比）页，形成愿景中的四页结构（Today / Assets / Goals / Insights）。

## 8. 风险与对策（评审结论的存档）

| 风险 | 对策 |
|---|---|
| 录入成本导致弃用（头号风险） | 原则 1/2；30 秒录入；月度轻校准；北极星指标守门 |
| 伪精确数字摧毁信任 | 原则 3/4；区间 + 假设面板；引擎只算账不裁决 |
| 范围膨胀 | 路线图分五期；Phase 1 非目标清单明确；能力/人生 ROI 锁死在远景层 |
| 残值无数据源 | 线性折旧 + 类目残值率默认值兜底，用户可手动录入二手行情估值 |
| 隐私（财务+行为数据集中） | self-hosted 单文件数据库；AI 可选且支持本地模型；见架构文档 §7 |
